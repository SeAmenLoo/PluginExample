# 角色资产生成工作流（细节形象图 + 全身像素图）

## 1. 目标

输入一套角色设定提示词（世界观、性别、年龄、职业、性格、种族、配色、关键词等），输出一套可用于 2D 游戏角色资产的图片：

1. 细节角色形象图 1 张
2. 全身像素图 1 张
3. 细节形象图的 4 张表情图：常态 / 喜 / 怒 / 哀
4. 全身像素图的 3 张动作图：站立 / 左脚前迈 / 右脚前迈

核心要求：

- 同一角色在两类图中保持身份统一：发型、脸型、五官、服饰结构、配色、标志性配件统一
- 不同角色之间保持产线风格统一：细节图的风格统一、像素图的风格统一、身体比例规则统一
- 文档优先基于火山引擎 Seedream 方案设计，同时给出更稳的增强方案

---

## 2. 推荐的产线原则

不要一次性直接生成“7 合 1 角色设定板”作为主流程。

更稳的做法是拆成两阶段：

### 阶段 A：先生成 2 张锚点图

1. 锚点 A：细节角色形象图
2. 锚点 B：全身像素站立图

这两张图不是最终资产，而是整套角色的一致性来源。

### 阶段 B：基于锚点图派生变体

1. 由锚点 A 派生 3 张表情变化图
2. 由锚点 B 派生 2 张行走差分图

原因：

- 先定锚，再派生，角色一致性明显高于一次性多图散射生成
- 表情变化只改脸部，动作变化只改腿部，改动面更小，更容易稳定
- 出问题时能定位是哪一段不稳：角色设计不稳，还是派生控制不稳

## 3. Seedream 能力边界与适配方式

根据火山引擎官方文档，Seedream 4.0/4.5/5.0 lite 支持：

- 文生图
- 单图生图
- 多参考图生图
- 组图生成

并明确支持“基于主体一致性的多图融合创作”。同时：

- 单图输出时，`sequential_image_generation = disabled`
- 组图输出时，`sequential_image_generation = auto`
- Seedream 4.x/5.0 支持多参考图输入
- 参考图数量 + 最终生成图片数量总和有上限

这意味着 Seedream 可以承担两类任务：

1. 用多参考图把“角色身份”和“目标风格”融合成新图
2. 用组图模式一次生成一组表情或一组动作

但从稳定性看，**主推荐不是一次生成所有图，而是“单图定锚 + 单图/小组派生”**。

参考：

- 官方教程：`https://www.volcengine.com/docs/82379/1824121?lang=zh`
- API 文档：`https://www.volcengine.com/docs/82379/1541523`

## 4. 角色一致性为什么会失控

要解决“同一角色统一”，先要拆开一致性的层次。

### 4.1 身份一致性

指这是不是“同一个人”：

- 脸型
- 眉眼鼻口关系
- 发际线
- 发型轮廓
- 年龄感
- 体型与肩宽

### 4.2 设定一致性

指角色配置是否一致：

- 服装结构
- 主辅配色
- 装备位置
- 饰品位置
- 材质倾向
- 职业标识

### 4.3 风格一致性

指画风是否统一：

- 细节图是否都在同一种插画语言里
- 像素图是否都在同一像素规则里
- 是否混入写实、二次元、厚涂、低清像素等冲突风格

### 4.4 比例一致性

指不同角色是否满足同一套生产规格：

- 细节图是半身还是三分之二身
- 像素图是二头身还是三头身
- 头身比是否统一
- 站姿视角是否统一

很多失败案例不是模型不行，而是把这四层约束混在一段提示词里，没有建立“固定项”和“可变项”。

## 5. 最小可执行方案：只用 Seedream

这是第一版最值得落地的工作流。

### 5.1 输入结构化

不要把用户输入直接拼成一句大 prompt。先把角色设定结构化成固定字段：

```json
{
  "worldview": "中世纪奇幻",
  "gender": "男",
  "age": "28",
  "race": "人类",
  "job": "游侠",
  "personality": "冷静、寡言、可靠",
  "body_type": "修长敏捷",
  "hair": "黑色中长发，后束低马尾",
  "face": "偏瘦长脸，锐利眉眼",
  "outfit": "深灰长风衣，皮革护腕，墨绿色围巾，长靴",
  "palette": "深灰、墨绿、旧银",
  "signature_items": "左肩披风，腰间短剑",
  "detail_style": "高细节角色设定稿，干净背景",
  "pixel_style": "经典JRPG像素风，三头身Q版，清晰像素块",
  "ratio_rule": "细节图为半身，像素图为三头身全身正面"
}
```

然后从结构化字段派生三类提示词：

1. 身份提示词
2. 风格提示词
3. 任务提示词

### 5.2 生成顺序

#### Step 1：先出细节锚点图

目标：

- 生成角色身份最清晰的一张图
- 这张图负责锁定脸、发型、服装结构、主配色

建议：

- 输出单图
- 干净背景或透明背景
- 姿态稳定，不要复杂动作
- 画幅以半身或 3/4 身为主

#### Step 2：由细节锚点图生成像素锚点图

输入：

- 细节锚点图
- 像素风格约束提示词

目标：

- 保留身份和服装信息
- 转成统一像素风、统一头身比、统一站姿的像素站立图

这里不要直接让模型“重新设计一个像素角色”，而要强调：

- 同一角色
- 保持发型、服装、配色、配件一致
- 仅改变表现媒介与身体比例规则

#### Step 3：由细节锚点图派生 3 张表情图

目标：

- 只改表情，不改发型、服装、镜头、姿势、配色

推荐做法：

- 逐张生成更稳
- 组图生成更快，但需要额外校验

#### Step 4：由像素锚点图派生 2 张步行动作图

目标：

- 只改腿部迈步状态和轻微手臂摆动
- 头部、服装、配色、视角、比例不变

推荐做法：

- 站立图先验收通过，再做左右脚差分

## 6. 最关键的统一性控制方法

### 6.1 固定“角色圣经”

每个角色在首次生成成功后，都要固化一份角色圣经（Character Bible）。

建议字段：

```json
{
  "character_id": "ranger_001",
  "identity_prompt": "28岁男性人类游侠，偏瘦长脸，锐利眉眼，黑色中长发，后束低马尾",
  "outfit_prompt": "深灰长风衣，墨绿色围巾，皮革护腕，旧银腰扣，腰间短剑",
  "palette_prompt": "深灰、墨绿、旧银，低饱和中世纪奇幻配色",
  "forbidden_changes": [
    "禁止更换发型",
    "禁止更换服装结构",
    "禁止更换主色调",
    "禁止更换脸型",
    "禁止新增其他人物"
  ],
  "detail_anchor_image": "detail_anchor.png",
  "pixel_anchor_image": "pixel_anchor.png"
}
```

后续所有表情图和动作图都从这份角色圣经派生，不再重新理解原始自然语言设定。

### 6.2 固定“风格圣经”

角色统一和项目统一是两件事。除了角色圣经，还要有风格圣经。

#### 细节图风格圣经

- 镜头：半身或 3/4 身
- 背景：纯白、透明或极简浅底
- 线稿/笔触：统一
- 光照：正向柔和工作室灯光或固定立绘光
- 材质表达：统一偏插画设定稿，不混写实摄影

#### 像素图风格圣经

- 视角：正面站立
- 头身比：统一三头身
- 画布：统一，例如 96x96 或 128x128
- 调色板上限：统一
- 描边规则：统一
- 阴影块数量：统一

不同角色之间的统一，主要依靠风格圣经，而不是角色 prompt 本身。

### 6.3 固定“可变项”和“不可变项”

每次生成都应明确：

#### 不可变项

- 人物身份
- 脸型
- 发型
- 服装结构
- 主配色
- 视角
- 身体比例

#### 可变项

- 表情
- 腿部步态
- 手臂轻微摆动

一条经验：**一次只允许一个维度变化。**

表情图只改表情。
动作图只改步态。

## 7. 针对你当前两种图的统一策略

你当前示例里，一张是高细节角色立绘，一张是低分辨率 JRPG 像素小人。这个组合天然容易失真，原因有两个：

1. 信息密度不对称：细节图包含太多局部设计，像素图承载不下
2. 比例系统不同：立绘偏真实比例，像素图偏三头身 Q 版

所以不能要求“像素图完全复制细节图的所有信息”，只能要求复制以下高优先级特征：

### 7.1 必须跨风格保留的特征

- 发型大轮廓
- 发色
- 脸型气质
- 服装外轮廓
- 1 到 2 个标志性配件
- 主色调与辅色调
- 职业识别点

### 7.2 可以在像素化时简化的特征

- 细碎花纹
- 微小金属零件
- 复杂褶皱
- 过多层次的皮革拼接
- 微表情

### 7.3 像素图统一的规则建议

所有角色强制：

- 三头身
- 正面站立基准图
- 同尺寸画布
- 同阴影层数
- 同调色板数量级
- 同脚底落点高度

否则不同角色放进游戏里会显得像来自不同素材包。

## 8. Prompt 设计方法

不要写一大段“文学描述”。建议采用分段模板。

### 8.1 细节锚点图 Prompt 模板

```text
【角色身份】
中世纪奇幻世界中的男性人类游侠，28岁，冷静寡言，修长敏捷，偏瘦长脸，锐利眉眼，黑色中长发，后束低马尾。

【服装与配色】
深灰长风衣，墨绿色围巾，皮革护腕，旧银腰扣，腰间短剑。主色调为深灰、墨绿、旧银。

【画面要求】
高细节角色设定稿风格，半身角色立绘，正面略微侧身，干净纯色背景，适合游戏角色设定图。

【硬性约束】
保持单人，禁止多角色，禁止更换发型，禁止更换服装结构，禁止更换主配色，禁止复杂背景，禁止文字水印。
```

### 8.2 像素锚点图 Prompt 模板

输入参考图：细节锚点图

```text
将参考图中的角色转换为经典 JRPG 像素角色站立图。

【保留项】
必须保留同一角色的发型轮廓、发色、脸部气质、服装结构、围巾、护腕、腰间短剑，以及深灰 + 墨绿 + 旧银配色。

【像素风规格】
经典 JRPG 像素风，三头身 Q 版比例，全身正面站立，清晰像素块，边缘锐利，有限调色板，干净背景，适合 2D 游戏角色精灵图。

【硬性约束】
同一角色，不得改成其他人，不得改变职业识别，不得新增背景和道具，不得写实化，不得模糊，不得出现多余人物。
```

### 8.3 表情派生 Prompt 模板

输入参考图：细节锚点图

```text
基于参考图生成同一角色的{喜悦/愤怒/哀伤}表情版本。
仅修改表情和极小幅度的眉眼嘴变化。
必须保持发型、脸型、服装、配色、镜头距离、身体朝向、背景、光照完全一致。
单人，干净背景，无文字水印。
```

### 8.4 动作派生 Prompt 模板

输入参考图：像素锚点图

```text
基于参考图生成同一角色的像素行走差分图：{左脚向前/右脚向前}。
仅修改腿部迈步状态和对应的轻微手臂摆动。
必须保持同一角色的发型、服装、配色、头身比、视角、像素风格、画布规格完全一致。
经典 JRPG 像素风，三头身 Q 版，全身正面。
```

### 8.5 负向约束模板

```text
禁止不同角色，禁止第二个人物，禁止不同发型，禁止不同脸型，禁止不同服装，禁止配色漂移，禁止写实摄影，禁止复杂背景，禁止文字，禁止水印，禁止模糊柔边，禁止低清噪点，禁止多余武器，禁止视角变化。
```

## 9. 推荐的 API 调用策略

### 9.1 锚点图用单图模式

原因：

- 输出最稳定
- 最易筛选
- 最容易做失败重试

适用：

- 细节锚点图
- 像素锚点图

### 9.2 表情图和动作图优先单图派生

虽然 Seedream 支持组图生成，但如果你把“喜怒哀 + 站立 + 行走左右脚”一次塞进去，角色身份和比例更容易漂。

更稳的顺序是：

1. 表情图逐张派生
2. 动作图逐张派生
3. 如果模型表现稳定，再优化成组图生成提速

### 9.3 组图模式适合什么

组图模式更适合：

- 已经有很稳的锚点图
- 同时生成 3 张表情或 3 张动作
- 目标是提升吞吐，不是首轮定稿

## 10. Seedream 接口落地建议

### 10.1 文生图 / 图生图基础字段

官方基础接口：

`POST https://ark.cn-beijing.volces.com/api/v3/images/generations`

常用字段：

- `model`
- `prompt`
- `image`
- `size`
- `output_format`
- `response_format`
- `watermark`

### 10.2 推荐模型

第一优先：

- `doubao-seedream-5-0-260128`

理由：

- 官方当前主推
- 支持文生图、图生图、多参考图、组图
- 支持 png 输出

### 10.3 锚点图示例

```bash
curl https://ark.cn-beijing.volces.com/api/v3/images/generations \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $ARK_API_KEY" \
  -d '{
    "model": "doubao-seedream-5-0-260128",
    "prompt": "高细节角色设定稿风格......",
    "size": "2K",
    "output_format": "png",
    "response_format": "url",
    "watermark": false
  }'
```

### 10.4 图生图示例

```bash
curl https://ark.cn-beijing.volces.com/api/v3/images/generations \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $ARK_API_KEY" \
  -d '{
    "model": "doubao-seedream-5-0-260128",
    "prompt": "将参考图中的角色转换为经典 JRPG 像素角色站立图......",

    "size": "2K",
    "output_format": "png",
    "response_format": "url",
    "watermark": false
  }'
```

### 10.5 多参考图的用法建议

多参考图最适合做这类融合：

1. 角色身份参考图 1 张
2. 项目像素风格参考图 1 到 3 张

例如：

- 图 A：当前角色细节锚点图
- 图 B：你项目里认可的标准像素角色样例

提示词里明确：

- 图 A 决定身份和服装
- 图 B 决定像素风格、头身比、渲染规则

这样比单纯让模型“凭文字理解像素风”更稳。

## 11. 建议增加一个自动质检层

不要把模型输出直接当成合格资产。

建议对每张图做 4 项人工或半自动验收：

### 11.1 身份验收

- 是否还是同一个人
- 发型是否一致
- 脸型是否明显变化

### 11.2 服装验收

- 主服装结构是否一致
- 标志配件是否丢失
- 主辅色是否偏移

### 11.3 风格验收

- 是否仍在项目约定风格内
- 是否混入写实 / 厚涂 / 其他像素规则

### 11.4 比例验收

- 像素角色是否仍为三头身
- 各角色脚底高度是否一致
- 站姿是否居中

如果后续要自动化，可以把验收问题做成一个 LLM/VLM 审核模板，让模型输出：

- pass / fail
- fail 原因
- 建议重试 prompt

## 12. 一致性失控时的修复顺序

一旦不统一，不要直接无限重抽。按下面顺序修：

### 情况 A：表情图像换了个人

处理：

1. 缩小变化范围，只允许改嘴角、眉形、眼神
2. 明确“其他部分完全一致”
3. 改为逐张单图派生
4. 以细节锚点图重新生成

### 情况 B：像素图服装变了

处理：

1. 增加“必须保留的服装结构”描述
2. 增加标准像素风参考图作为第二参考
3. 降低原 prompt 中世界观叙事性描述，提升结构描述密度

### 情况 C：不同角色像素比例不一致

处理：

1. 固定画布尺寸
2. 固定三头身规则
3. 固定站姿模板
4. 给所有角色共用同一条像素风 prompt 模板

### 情况 D：项目里不同角色细节图风格漂移

处理：

1. 固定统一的细节图风格模板
2. 固定背景、镜头、光照
3. 保留角色差异，只让“身份字段”变化

## 13. 更稳的增强方案

如果 Seedream-only 方案跑通后还觉得一致性不够，推荐两条增强路线。

### 13.1 方案 A：Seedream + 后处理像素化

思路：

1. 用 Seedream 生成高质量细节锚点图
2. 生成一个高分辨率 Q 版全身设定图
3. 再用像素化工具或专门像素模型做降采样和人工修像素

优点：

- 角色身份更容易保住
- 最终像素图更方便人工修整

缺点：

- 自动化程度稍低
- 像素味道可能不如原生像素模型

适合：

- 主角、重要 NPC
- 对可读性要求高的项目

### 13.2 方案 B：开源工作流做强一致性

典型组合：

- FLUX / SDXL 基模
- LoRA：学习角色身份或项目画风
- IP-Adapter：注入角色参考图
- ControlNet / Pose：约束动作和构图

推荐用途：

- 一名角色要出很多姿态
- 多个角色都要服从同一风格规约
- 需要长期复用而不是一次性出图

经验上：

- 参考图能快速锁身份
- LoRA 更适合长期复用
- Pose 控制适合动作差分

也就是说，**Seedream 更适合先跑通生产，LoRA/IP-Adapter/ControlNet 更适合把一致性做成资产生产线。**

---

## 14. 面向项目的推荐版本

如果你现在要尽快产出可用流程，我建议按下面版本推进：

### V1：先跑通

- Seedream 文生图生成细节锚点图
- Seedream 图生图把细节锚点图转成像素锚点图
- Seedream 单图派生 3 张表情图
- Seedream 单图派生 2 张步行动作图
- 人工验收

### V2：稳定化

- 为每个角色存角色圣经 JSON
- 为项目存风格圣经 JSON
- 增加标准像素风参考图
- 引入自动质检脚本

### V3：工业化

- 重要角色训练角色 LoRA
- 动作图用姿态控制
- 像素图统一走固定后处理
- 建立失败重试和版本回滚

## 15. 推荐的数据组织方式

```text
CharacterAssets/
  ranger_001/
    spec.json
    style_rules.json
    detail/
      anchor.png
      normal.png
      happy.png
      angry.png
      sad.png
    pixel/
      anchor_stand.png
      walk_left.png
      walk_right.png
    review/
      qa.md
```

`spec.json` 负责角色身份。

`style_rules.json` 负责项目风格规则。

这样后续要重新生成某一张图，不需要重新读自然语言需求。

## 16. 结论

这套需求最重要的不是“把 prompt 写得更长”，而是把流程改成：

1. 先定 2 张锚点图
2. 再做小范围派生
3. 用角色圣经锁身份
4. 用风格圣经锁项目统一
5. 把像素风比例和画布规格做成硬规则

对当前目标，**最务实的首选方案是 Seedream 5.0 + 单图定锚 + 单图派生**。

如果后续要大批量生产角色，或者要显著提高跨角色一致性，下一步就该上：

- 多参考图融合
- 自动质检
- LoRA / IP-Adapter / Pose 控制
